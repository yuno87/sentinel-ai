# Changelog

Dated changes since Milestone 1. Commit history on GitHub shows the same work.

## 2026-11-21: Real runs, fixes and deployment
- Ran the prompt experiment (v1 to v4) and the 15 test inputs on Gemini 3.5 Flash-Lite; all raw outputs saved in `test-data/outputs/`.
- Prompt v4: rewrote P3 (predict reply) after v3 judged only 2 % of attacks as Fail; v4 judged 31 %, ranked by how weak each bot is.
- Fixed a bug found by test T07: the schema conversion dropped a field named "title", so the hardening step failed. Added a regression test.
- Deployment moved from Hugging Face Spaces (needs a paid plan for apps that run code) to Vercel: `index.py`, root `requirements.txt`, `vercel.json`.
- Added the four diagrams, real sample runs for the prompt sheets, the technical report and the Milestone 2 PDF builder.

## 2026-11-20: Gemini support (free key)
- Added a Gemini client (`google-genai` SDK, model `gemini-3.5-flash-lite`) next to the Claude one. The app picks the AI from whichever key is set: Claude, then Gemini, else demo mode.
- Gemini uses structured JSON output (`response_json_schema`) and waits and retries automatically when the free per-minute limit is hit.
- Prompt sheets now name Gemini 3.5 Flash-Lite as the model used for the Milestone 2 runs.
- Added the four diagrams in `docs/diagrams/` (generated by `code/tools/make_diagrams.py`).

## 2026-11-20: "Not tested" verdict
- When no attack could be judged (for example the chatbot was unreachable), the launch call is now **Not tested** instead of "No failures found", which wrongly suggested the bot was safe. Found by test input T15.

## 2026-11-20: No API key needed
- The app switches to demo mode automatically when no API key is set, so it runs with no setup. `demo.env` is no longer needed and was removed.
- With a key in `code/.env`, the real model is used automatically.
- The test runner and prompt experiment still require a key, since their results must be real model output.

## 2026-11-20: Milestone 2 preparation
- Reorganised the repository into the required layout: `prompts/` (v1, v2, v3, final), `code/`, `test-data/`, `docs/`.
- Turned each prompt's user message into a plain template with `{variables}`, so the prompt sheets match the code exactly.
- Added `code/tools/export_prompts.py`, which writes the 5 final prompts (P1 to P5) to `prompts/final/`.
- Saved the Milestone 1 baseline prompt as `prompts/v1/`.
- Added the v2 prompts (attack writer + combined predict-and-judge) and `code/tools/prompt_experiment.py`, which runs v1, v2 and v3 on the same 3 test chatbots and measures format, coverage, tailoring, safety, verdicts and evidence.
- Added 15 test inputs (`test-data/inputs/`: 7 Normal, 5 Edge, 3 Invalid) and `code/tools/run_tests.py`, which runs them through the app's API and saves every output plus a test table. It refuses to run in demo mode.
- Added team guides: setup, testing guide, experiment guide, iteration log template, reel script.
- Found while building the test runner: when every attack errors (unreachable chatbot), the launch call still says "No failures found" (test T15).

## 2026-11-13: Fix for report not loading
- The page now tells the browser to always fetch the newest page files, so an old `app.js` can't call routes the server doesn't have.
- Clear "restart the server" message instead of a bare "Not Found".
- Start commands use `--reload` so the server picks up code changes.

## 2026-11-13: Usability redesign
- Three tabs: Setup, Report, Fix & re-test.
- One "Scan my chatbot" button with a live progress checklist (attacks run one by one so progress can be shown).
- Plain-English names for attack types, ⓘ tooltips for every term, a plain-language launch verdict.
- Live mode presets and a "Test connection" button.

## 2026-11-13: First working build
- Replaced the Milestone 1 single prompt with a 5-step pipeline, each step its own prompt: P1 Analyse, P2 Attacks, P3 Predict, P4 Judge, P5 Harden.
- Structured JSON output validated with Pydantic, instead of free-text lines.
- Judging moved to a separate call from the reply, with evidence quotes checked by code.
- Added a fourth attack category, prompt injection through pasted content (indirect injection), following the reviewer feedback from Milestone 1.
- Fixes split into prompt changes and application changes, plus a hardened prompt, diff view and re-test (the "mitigation" part of the Milestone 1 feedback).
- Live mode: send attacks to a real chatbot endpoint. Practice chatbot included.
- Markdown and CSV export. Demo mode for running without an API key.
- Uses Claude (Opus 5.5) for every step instead of the three models planned in Milestone 1, to keep one consistent, structured-output pipeline.
